## الغرض

مرجع أساسي يستخدمه النظام عند تحليل أو بناء أو تطوير أو تحسين أي مشروع خدمي أو B2B، ويجب الرجوع إليه قبل اقتراح الأنظمة أو العمليات أو الخطط التشغيلية.

هذا المصدر هو **Operating Logic (منطق تشغيل)**: يوجه الأسئلة، وترتيب الفجوات، وتصميم التحسين، وتنظيم العرض أو الـSOP، وتلخيص التعلم. لا يثبت حالة أي عميل، ولا ينشئ قرارًا أو فرصة أو خدمة أو KPI دون أدلة الحالة وBaseline واعتماد بشري.

## القواعد المعرفية

1. لا خدمة بدون مشكلة واضحة، عميل محدد، ونتيجة قابلة للقياس.
2. التشخيص يسبق التنفيذ.
3. يجب تحديد Baseline (خط الأساس) قبل أي تحسين.
4. فصل Core System (النظام الأساسي) عن Sector Modules (الوحدات القطاعية).
5. أي عملية متكررة تتحول إلى Standard Operating Procedure (SOP) — إجراء تشغيل قياسي.
6. لكل مهمة Owner (مسؤول) واحد واضح.
7. كل مشروع يجب أن يحدد: Scope (النطاق)، Timeline (الجدول الزمني)، Deliverables (المخرجات)، Budget (الميزانية)، Quality Criteria (معايير الجودة)، KPIs (مؤشرات الأداء الرئيسية)، Risks (المخاطر).
8. لكل مخرج Definition of Done (تعريف اكتمال العمل).
9. لا تسعير دون معرفة التكلفة والهامش وUnit Economics (اقتصاديات الوحدة).
10. كل فرصة تدخل Customer Relationship Management (CRM) — إدارة علاقات العملاء ولها Next Action (الإجراء التالي).
11. الموردون والمستقلون يخضعون لتقييم الجودة والالتزام والسعر وإعادة العمل.
12. الشركة تحتفظ بملكية بيانات العميل والملفات والمعرفة والعلاقة.
13. لا Automation (أتمتة) قبل إثبات العملية يدويًا.
14. القرارات المهمة تحفظ في Decision Register (سجل القرارات).
15. كل مشروع يجب أن ينتج معرفة قابلة لإعادة الاستخدام.
16. الخدمات تراجع دوريًا حسب الربحية، الجودة، القيمة، قابلية التكرار، وقابلية التوسع.

## الأنظمة المرجعية

1. Strategy & Opportunity System (نظام الاستراتيجية والفرص).
2. Product & Offer System (نظام المنتجات والعروض).
3. Sales Operating System (نظام تشغيل المبيعات).
4. Customer Relationship Management (CRM) — إدارة علاقات العملاء.
5. Project Delivery System (نظام تسليم المشاريع).
6. Finance & Profitability System (نظام المالية والربحية).
7. Vendor & Partner System (نظام الموردين والشركاء).
8. Quality Management System (نظام إدارة الجودة).
9. Knowledge Management System (نظام إدارة المعرفة).
10. Data, AI & Automation System (نظام البيانات والذكاء الاصطناعي والأتمتة).

## دورة العمل المرجعية

**Opportunity → Qualification → Diagnostic → Baseline → Bottleneck → Solution Design → Proposal → Delivery → Quality Assurance → Collection → Results → Renewal/Expansion → Knowledge Capture**

**فرصة → تأهيل → تشخيص → خط أساس → تحديد الاختناق → تصميم الحل → عرض → تنفيذ → ضمان الجودة → تحصيل → نتائج → تجديد/توسع → حفظ المعرفة.**

## قاعدة الاستخدام

عند تحليل أي مشروع أو تطويره، استخدم هذا المصدر كـ Operating Logic (منطق تشغيل) وليس كنص جاهز للنسخ. استخرج منه القواعد المناسبة للحالة، واربطها بالبيانات الفعلية للمشروع، ولا تفترض معلومات غير موجودة.

قبل اقتراح تحسين أو قرار، يجب أن يوضح سنع:

- المشكلة والعميل والنتيجة المطلوبة.
- Baseline والدليل ومصدر كل معلومة.
- ما هو Fact أو Evidence، وما هو Assumption أو Hypothesis أو Inference أو Forecast أو Risk أو Recommendation.
- الفجوة التي تمنع القرار، وما المطلوب للتحقق منها.
- صاحب الاعتماد البشري ومعيار نجاح الإجراء وحد إيقافه.

## الهدف النهائي

تحويل المشاريع الخدمية وB2B من أعمال تعتمد على الأشخاص والاجتهادات إلى Corporate Operating Manual (COM) — دستور تشغيل الشركة مترابط، قابل للقياس، التوسع، الأتمتة، ونقل المعرفة.

هذا الهدف اتجاه تشغيلي عام، وليس توقعًا مضمونًا أو Benchmark رقميًا. لا يُستخدم المصدر وحده لإصدار قرار خاص بمشروع أو لفتح بيانات `research_sources` الخاصة.
