---
name: Sana Expert system prompt integration
description: How to integrate a user-supplied Claude system prompt with existing extraction code that expects specific hidden output markers.
---

When a feature's backend already parses specific hidden markers out of an LLM's reply (e.g. an HTML-comment JSON block for structured extraction, or a checkpoint marker for stage progression), a user-authored system prompt handed over later for "verbatim" use will very often describe the desired *conversation behavior* in detail but say nothing about the *technical output format* the code needs — because the user is thinking about the expert/user experience, not the extraction plumbing underneath.

**Why:** In the "سنع الخبير" (Sana Expert) feature, the backend `/api/e/<slug>/chat` route was built first and regex-parses `<!-- FACTS_JSON: [...] -->` and `<!-- STAGE_CHECKPOINT: N -->` out of Claude's raw reply before stripping them from the displayed text. When the user supplied the real 7-stage system prompt "to be used literally," it defined rich dialogue rules and a *human-readable* decision log format (`الحقيقة | الدليل | القرار | درجة الثقة`) but never mentioned the hidden JSON markers. Using the prompt verbatim as-is would have silently broken fact extraction and stage-checkpoint detection in production, even though everything tests fine in isolation.

**How to apply:** Don't edit or paraphrase the user's verbatim content, and don't rewrite the extraction code to match their human-readable format (bigger, riskier change, and the DB schema/fact_type categories were already agreed). Instead, append a clearly delimited "technical appendix" section at the end of the prompt (own `##` heading, explicitly marked "for the system only, never shown to the expert") that gives Claude exact instructions for the hidden markers, reusing the same categories/vocabulary the user's own prompt already established (e.g. mapped their confidence labels مؤكد/مرجح/افتراض/غير محسوم onto the existing `confidence_level` field). State this decision transparently to the user afterward rather than silently altering their text. Verify by round-tripping a real multi-turn Claude conversation and checking the DB, not just a single reply.
