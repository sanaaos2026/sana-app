# SDS-002 — Sana Progressive Discovery (MVP فقط)

```
STATUS: MVP READY FOR IMPLEMENTATION
GOVERNS: GOVERNANCE-001 (الفصل بين الرؤية والتنفيذ)
FULL VISION (Question Scoring Engine, Knowledge Graph, Recommendation Engine): VISION ONLY — NOT FOR IMPLEMENTATION NOW
```

هذا الملف **جزء تنفيذي فوري**، لا رؤية مؤجَّلة — لكن بنسخة مبسّطة جدًا من الفكرة الكاملة. الفرق بينه وبين وثيقة الرؤية الأصلية: هنا صفر محركات جديدة، فقط قواعد اختيار بسيطة (If/Else) فوق جداول موجودة فعليًا.

---

## الفكرة (بجملة واحدة)

بعد أي تحليل (جواز الشركة أو صفحة القضية)، سنع يسأل **سؤالًا واحدًا أو اثنين بس** — مو استبيانًا كاملًا — يستهدف أضعف نقطة معرفة عنده حاليًا عن الشركة.

---

## مكتبة الأسئلة (ثابتة بالكود، لا جدول جديد الآن)

5 أصول × سؤال واحد لكل أصل. تُخزَّن كـ `dict` بسيط داخل `app.py` — **ليست جدولًا بقاعدة البيانات** (لا حاجة لهذا التعقيد بمرحلة MVP؛ لو أثبتنا لاحقًا احتياج فريق المحتوى لتحرير الأسئلة بلا نشر كود، حينها فقط تُنقل لجدول — قرار مؤجَّل).

| الأصل | السؤال | الخيارات |
|---|---|---|
| Knowledge | هل إجراءات العمل الأساسية عندكم موثقة؟ | نعم / جزئيًا / لا |
| Brand | هل يقدر أغلب عملائك يوصفون شركتك بجملة وحدة؟ | نعم / لا / ما أعرف |
| Operations | هل يوجد شخص يقدر يأدي عملك لو غبت أسبوعين؟ | نعم / جزئيًا / لا |
| Data | هل عندكم لوحة متابعة أسبوعية للمبيعات أو الأداء؟ | نعم / قيد الإعداد / لا |
| Independence | كم قرار يحتاج موافقتك الشخصية تقريبًا كل يوم؟ | قليل (0-2) / متوسط (3-6) / كثير (+7) |

## قاعدة الاختيار (بسيطة، حتمية، بلا محرك)

```
لكل أصل من الأصول الخمسة:
    عدّ عدد صفوف evidence المرتبطة به لنفس الشركة
    → هذا هو "مستوى الثقة" التقريبي (Confidence Proxy)
      لا عمود confidence جديد — يُشتق من COUNT(evidence) مباشرة

اختر الأصل صاحب أقل عدد أدلة
اعرض سؤاله من المكتبة أعلاه

لا تعرض أكثر من سؤالين بعد أي صفحة تحليل واحدة (جواز أو قضية)
إذا كان الأصل الأقل ثقة عنده دليل واحد على الأقل فعلاً → لا تسأل عنه إذا كل الأصول متساوية بعدد الأدلة، اختر عشوائيًا بينها
```

**بلا Question Scoring Engine، بلا Knowledge Gap Detector، بلا Recommendation Engine** — كلها مؤجَّلة (VISION ONLY).

## واجهة العرض

**التسمية:** 🧩 بقيت فجوة واحدة… *(بدل "تشخيص سريع" — نفس اقتراح الوثيقة، يعطي إحساس مستشار لا استبيان)*

**مكان الظهور:** أسفل صفحة `/passport` وأسفل صفحة `/case/<id>` — قسم صغير جديد، لا صفحة منفصلة.

**بعد الإجابة:** رسالة قصيرة تختفي بانسياب: "تمام، ارتفعت معرفتنا بهذا الأصل 🎯" — بلا احتفال مبالغ فيه.

**قاعدة المهام المقترحة (التعارض المحلول):**
إذا كانت الإجابة تستحق اقتراح إجراء (مثال: أجاب "لا" على سؤال التوثيق) → **يُعرض نص اقتراح فقط بالواجهة** ("💡 يُنصح بالبدء بتوثيق إجراءات خدمة العملاء") — **لا يُنشأ صف حقيقي بجدول `tasks`**، لأن ذلك يتطلب `decision_id` غير موجود هنا، والقرار يحتاج دليلًا وسببًا فعليين قبل أي إنشاء — نفس انضباط v3-FINAL بالضبط.

## التخزين (الخانات الخمس — GOVERNANCE-001)

1. **Storage Destination:** `evidence` (نفس الجدول والـendpoint المستخدم في Discovery وassessment — أعد استخدام نفس نمط الحفظ الناجح والمختبر، لا نمطًا جديدًا)
2. **Case Link:** القضية الأولى للشركة (نفس `case_id` بالجلسة)
3. **Asset Link:** معرّف الأصل الحقيقي (`{company_id}-A00X`) — تحقق من وجوده فعليًا بجدول `assets` قبل أي محاولة حفظ
4. **Framework Link:** N/A — لا علاقة بأي إطار عمل هنا
5. **Business Event:** N/A — Deferred

## نص جاهز للوكيل

```
هذا تنفيذ MVP لفكرة "تشخيص تراكمي" (SDS-002) — تحسين فوق /passport و/case/<id> الموجودين، بلا أي محرك أو جدول جديد عدا استثناء واحد صغير موضح أدناه.

نفّذ فقط التالي:

1. أضف dict ثابت بـapp.py يحوي 5 أسئلة (سؤال واحد لكل أصل من الأصول الخمسة الموجودة) — النص والخيارات موجودة بالملف المرفق SDS-002-progressive-discovery-MVP.md.

2. اكتب دالة اختيار بسيطة: لكل أصل، عدّ evidence المرتبطة به لنفس الشركة (COUNT مباشر، بلا عمود confidence جديد)، اختر الأصل الأقل عددًا، اعرض سؤاله. لا تعرض أكثر من سؤالين بعد أي صفحة تحليل واحدة.

3. أضف قسمًا صغيرًا بعنوان "🧩 بقيت فجوة واحدة…" أسفل /passport وأسفل /case/<id>، يعرض السؤال المُختار.

4. عند الإجابة: احفظها كـ evidence بنفس الـendpoint والنمط المستخدم فعليًا بصفحة assessment (بعد ما تتأكد هو نفسه شغّال ومصلَّح من الطلب السابق) — لا تنشئ أي جدول أو عمود جديد لهذا.

5. استثناء واحد فقط مسموح: إذا كانت الإجابة تستحق اقتراح إجراء، اعرض نص الاقتراح بالواجهة فقط (Frontend، لا Backend) — لا تنشئ أي صف بجدول tasks أو decisions لهذا السبب. tasks يتطلب decision_id موجود فعليًا، وما عندنا قرار حقيقي هنا بعد.

6. لا تبني: Question Scoring Engine، Knowledge Graph، Recommendation Engine، أو أي نسبة "Knowledge %" مركّبة — كلها مؤجَّلة رسميًا (VISION ONLY) حسب GOVERNANCE-001 المعتمد بجذر المشروع.

اختبر فعليًا: افتح /passport لحساب تجريبي، تأكد يظهر سؤال واحد للأصل الأقل أدلة، جاوب عليه، تأكد الدليل انحفظ فعليًا بالقاعدة (تحقق مباشرة، لا افتراضًا)، وتأكد السؤال التالي يختلف (أصل مختلف) بعد ما يرتفع عدد أدلة الأصل الأول.

أرسل لقطات فعلية من الدومين المنشور بعد التنفيذ.
```
