نبني ميزة جديدة كاملة: "سنع الخبير" — أداة اكتشاف وتأهيل خبراء عبر محادثة ذكية، منفصلة تمامًا عن نظام الشركات/القضايا الحالي.

⚠️ قاعدة حاكمة يجب تطبيقها بصرامة في كل هذي الميزة:
لا تعرض أي رقم أو نسبة مئوية لا يمكن تفسير طريقة احتسابها للمستخدم. الأرقام نوعان فقط:
(أ) عدّادات مباشرة من قاعدة البيانات (مثل: 18 حقيقة مكتشفة، 12 دليل مرفق) — هذي مسموحة دائمًا
(ب) مؤشرات مشتقة بصيغة "X من Y عناصر مكتملة" مع قائمة صريحة تحقق (✔/✖) لكل عنصر — ممنوع أي نسبة مئوية مجردة بدون قائمة تحقق ظاهرة خلفها
ممنوع تمامًا أي مؤشر يشبه "قابلية التحويل إلى AI: 82%" بدون تفسير محسوب.

═══ الجزء 1: البنية التحتية (ابدأ هنا) ═══

أنشئ كيانًا جديدًا مستقلًا تمامًا عن جدول leads:

جدول experts:
- expert_id (PK, نص، مثل EXP-104)
- uuid (فريد داخلي)
- name, domain_expertise, phone (اختياري), email (اختياري), notes
- access_link_slug (الجزء اللي يظهر في الرابط)
- access_code (6 أرقام، اختياري - null لو ما فُعل)
- status (لم يبدأ / بدأ الاكتشاف / يحتاج استكمال أدلة / وصل للمشاريع المقترحة / اعتمد المشروع / بدأ بناء النظام / جاهز لجلسة مستشار / تحول لمشروع فعلي)
- created_at, last_session_at

جدول expert_sessions:
- session_id (PK)
- expert_id (FK)
- started_at, ended_at (null لو مستمرة)
- current_stage (1-7 حسب مراحل البرومبت)
- conversation_log (JSON: كامل تبادل الرسائل)

جدول expert_facts:
- fact_id (PK)
- expert_id (FK)
- session_id (FK)
- fact_type (حقيقة / دليل / افتراض / فرصة / خطر / قرار)
- content (نص)
- confidence_level (مؤكد / مرجح / افتراض / غير محسوم) - فقط لنوع "حقيقة" أو "قرار"
- related_stage (رقم المرحلة اللي استُخرج فيها)
- created_at

جدول expert_knowledge_assets:
- asset_id (PK)
- expert_id (FK)
- asset_category (مبدأ / قاعدة / نموذج / قائمة / سؤال / خطأ شائع / معيار / مصطلح / قصة / دراسة حالة / اختصار)
- content (نص)
- transformable_to (JSON array: خدمة/منتج رقمي/دورة/وكيل AI/أداة/SOP/محتوى)

جدول expert_projects (المشاريع الخمسة المقترحة + المرشح):
- project_id (PK)
- expert_id (FK)
- title, description
- scores (JSON: كل معايير التقييم الأربعة عشر المذكورة في البرومبت، كأرقام من 10 لكل معيار - هذي مسموحة لأنها تقييم صريح لكل معيار منفصل، مو رقم نهائي مجمّع مصطنع)
- is_recommended (boolean - واحد فقط true لكل خبير)
- recommendation_reason (نص)

اختبر بنية الجداول بإدخال بيانات وهمية بسيطة والتأكد من الروابط (FK) تعمل، ثم امسحها. أعطني تقرير ببنية الجداول والنتيجة قبل ما تكمل للجزء 2.

═══ الجزء 2: لوحة تحكم إدارة الخبراء ═══

صفحة إدارية (تتطلب تسجيل دخول المستشار/المدير - استخدم نفس نظام user_accounts الحالي، ليس حساب شركة):
- زر "➕ خبير جديد" يفتح نافذة: اسم، مجال، جوال (اختياري)، بريد (اختياري)، ملاحظات
- عند الضغط "إنشاء": يولد النظام تلقائيًا UUID + رمز قصير EXP-XXX (تسلسلي) + رابط دائم (مثال: sanaclarity.com/e/EXP-104) + رمز دخول 6 أرقام عشوائي
- يعرض الرابط والرمز فورًا مع زر نسخ لكل منهما
- جدول يعرض كل الخبراء: الاسم، المجال، الحالة، نسبة اكتمال بصيغة "X من 7 مراحل"، آخر جلسة، عدد الأصول المعرفية المستخرجة (عدّاد حقيقي)
- عند الضغط على خبير: يفتح ملفه بنفس واجهة الخبير (القسم 3) لكن بصلاحيات إدارية (يشوف كل شي، ما يحتاج رمز دخول)

═══ الجزء 3: واجهة الخبير (الصفحة العامة المحمية) ═══

المسار: /e/<access_link_slug>
- يطلب رمز الدخول (6 أرقام) أول مرة، ثم يحفظ الجلسة (session) عشان ما يطلبه كل مرة
- صفحة ترحيب: "خبرتك أكبر من أن تبقى داخل رأسك" + زر "ابدأ تحويل خبرتي"
- محادثة تفاعلية تطبّق البرومبت الكامل بمراحله السبع (سأعطيك نص البرومبت الكامل في رسالة منفصلة بعد هذا الأمر لأنه طويل جدًا - جهّز البنية لاستقباله كـ system prompt لاستدعاء Claude API)
- بعد كل إجابة من الخبير: استخرج من رد Claude العناصر (حقيقة/دليل/افتراض/فرصة/خطر/قرار) واحفظها في expert_facts، واعرض للخبير بطاقة مختصرة (أهم 3 عناصر فقط كما هو موصوف)
- نقاط توقف بعد كل مرحلة: اعرض ملخص واطلب "اعتمد / عدّل / أضف دليلاً / غير دقيق" قبل الانتقال للمرحلة التالية
- تبويبات ثمانية أعلى الصفحة: المحادثة / الحقائق / الأدلة / الفرص / المشاريع / الأصول المعرفية / نظام التشغيل / التقرير النهائي - كل تبويب يعرض بيانات expert_facts/expert_knowledge_assets/expert_projects المرتبطة فعليًا، بدون بيانات وهمية لو التبويب فارغ ("لا يوجد بعد")

مؤشرات الشريط الجانبي (عدّادات حقيقية فقط، راجع القاعدة الحاكمة أعلاه):
✅ الحقائق المكتشفة: [عدد فعلي] · 📎 الأدلة: [عدد فعلي] · 🎯 الفرص: [عدد فعلي] · 📋 القرارات المعتمدة: [عدد فعلي] · ❓ الافتراضات قيد الاختبار: [عدد فعلي] · 🧠 الأصول المعرفية: [عدد فعلي]

مؤشر "جاهزية بناء النظام" (مشتق، مش نسبة): اعرض قائمة تحقق صريحة (هوية الخبير ✔/✖، العميل المثالي ✔/✖، المشكلة الأساسية ✔/✖، دليل نتائج ✔/✖، نموذج الإيرادات ✔/✖، رحلة العميل ✔/✖، مؤشرات الأداء ✔/✖) والنتيجة "X من 7 عناصر مكتملة"

═══ الجزء 4: التقرير النهائي ═══

بعد اكتمال المراحل السبع (أو عند طلب الخبير في أي وقت): صفحة "خريطة مشروعك" تجمع كل الأقسام الثلاثة عشر المذكورة (هوية الخبير، رأس المال المعرفي، العميل، المشكلة، المشاريع الخمسة، المشروع المرشح، مبرراته، نموذج الإيرادات، المنتجات، نظام التشغيل، الأصول المعرفية، خطة أول 30 يومًا، الأسئلة بلا دليل) - كل قسم من بيانات فعلية محفوظة، لا نص افتراضي
زر "تحميل كملف Markdown" كخطوة أولى (لا تبني PDF/Word/Notion الآن - هذي تحتاج مكتبات إضافية، نضيفها بعد ما نتأكد إن المحتوى نفسه صحيح)

═══ ملاحظات أمان مهمة ═══
- رمز الدخول (6 أرقام) يجب أن يكون له rate limiting: 5 محاولات خاطئة كحد أقصى، ثم قفل مؤقت 15 دقيقة
- كل استدعاء لـ Claude API في المحادثة يجب أن يُسجَّل (لمراقبة التكلفة لاحقًا) - أضف حقل بسيط لعدّاد الاستدعاءات لكل expert_id
- لا تخلط هذا النظام بجداول company_id / user_accounts الخاصة بالشركات الحالية - هذا نظام منفصل بالكامل بجداوله الخاصة

ابدأ بالجزء 1 فقط الآن (البنية التحتية)، واعطني تقريرًا كاملاً بالجداول والنتيجة، وانتظر تأكيدي قبل الانتقال للجزء 2.
